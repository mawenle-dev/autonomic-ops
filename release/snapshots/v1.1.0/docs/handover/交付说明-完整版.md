## 1. 问题逐条回应

| 提出的问题 | 处理结果 |
|---|---|
| Windows 降级代码本质上删了吗 | **已删**：sandbox 非 POSIX 降级、`_kill_group` Windows 分支、`util.which` 的 PATHEXT 分支、collectors 无 `/proc` 返回空列表，全部移除；改为 `platform_guard.require_linux()` **明确拒绝**（非 Linux 抛 `UnsupportedPlatform`）。文档中"Windows 也可用/优雅降级"表述已改。发布台是唯一跨平台组件（本地 Web 控制台）。 |
| Windows 上运行核心能力的处理 | 已移除。核心能力（沙箱/采集/daemon）在非 Linux 上不再运行；测试在非 Linux 上 `skip` 并断言“明确拒绝”。 |
| 彻底审查代码与文档确认 | 已 grep 全部 `os.name=="nt"/platform.system/win32/Windows` 并逐处处理；README/KNOWN_GAPS/CHANGELOG/交付文档已改。 |
| 第二天发布会不会覆盖原有 | **不会**。新版本 = 新 tag + 新 Release；同名资产 GitHub 返回 422，本项目**不删除不替换**，直接拒绝（`release_exists_no_overwrite` / `asset_exists_no_overwrite`）。 |
| 120 版每版都有独立文档吗 | **有**：`release/docs/<版本>.md` 共 120 份 + `INDEX.md`；每份含本版新增/优点/验收/验证入口/升级回滚。项目总文档（CHANGELOG/本文件）同步更新。 |
| 一键发布能同步到 GitHub 吗 | 已实现 `tools/publish_release.py` 与 `ReleaseStudio.publish_github()`；**默认 dry-run**，必须 `--confirm PUBLISH` 才发；`--push-docs` 才推文档。**本次未执行发布。** |
| 有没有联网调研 | 有，见第 7 节（GitHub 官方 API/不可覆盖语义；Sparkle 全量+增量+EdDSA 更新模型）。 |
| 本地能不能用代码建快照更新 | 能。`snapshot_update.py`：Ed25519 验签 + 逐文件 sha256 + 原子替换 + 回滚 + 拒绝路径穿越；7 项测试。 |
| 别人是用快照更新吗 | 是主流做法：全量快照为事实来源，增量为优化（Sparkle）。本项目先做正确的全量签名快照，不生成 delta。 |

## 2. 平台与验证环境

- **目标平台**：Linux（systemd、/proc、AF_UNIX、nftables/iptables）。非 Linux 明确拒绝，不降级。
- **验证环境**：Ubuntu 24.04，内核 `6.8.0-147-generic`，x86_64，SSH `127.0.0.1:2222`。
- Windows 仅用于编辑代码与 PyInstaller 打包。

## 6. 逐版本文档与发布机制

- 逐版本文档：`release/docs/1.0.1.md` … `release/docs/3.0.3.md`（120 份）+ `INDEX.md`。
- 发布机制详见 `docs/RELEASE.md`：追加式、不覆盖、默认 dry-run、token 放 `.secrets/github_token`（已 gitignore）。
- 快照更新：`src/autonomic/snapshot_update.py`（签名/哈希/原子/回滚）。
- 一键发布：`python tools/publish_release.py --version X --asset ...`（默认只计划）。

## 7. 调研依据（已核对）

1. **GitHub Create a release**：`POST /repos/{owner}/{repo}/releases`，新 tag 生成新 Release。
2. **GitHub Upload release asset**：`POST .../releases/{id}/assets?name=...`；**同名返回 422，必须先删除旧资产**；GitHub 另有 immutable releases 选项。→ 本项目永不删除/覆盖。
3. **桌面更新模型**：Sparkle（macOS）采用全量 zip + 可选 delta（`sparkle:deltaFrom`）+ EdDSA 签名 + 原子安装/回滚；全量快照是事实来源。→ 本项目采用签名快照 + 原子替换 + 回滚，不生成 delta。

## 8. 仍然诚实的边界

1. 探针协议握手对**本地真实服务**验证，未连真实外部第三方。
2. 解码器样本为代表性日志，未穷尽厂商变体。
3. 审计为自跑断言，非第三方独立验收；报告 `audit-report.json` 可逐条复核。
4. EXE 用 HTTP 接口实测，未人工逐按钮点击。
5. **未发布**：未 push、未打 tag、未创建 GitHub Release；该步骤需要维护者的写权限与令牌。
6. 密钥运维界面未产品化；delta 更新未实现（先保证全量快照正确）。
