# 能力对照与吸收说明

## 说明

本节只记录“吸收了哪些设计思想、在本项目如何独立实现”，不涉及第三方源码。
所有条目均为本项目自行设计，接口、数据结构与实现方式与来源项目不同。

## 2. 分类对照

| 能力域 | 常见开源做法 | 本项目实现 | 状态 |
|---|---|---|---|
| 进程守护 | systemd/runit/s6 的拉起、退避、日志 | 内置 supervisor + pidfile + 看门狗；日志轮转入隔离区 | 已实现 |
| 配置收敛 | Ansible/Salt/Puppet 的声明式幂等 | 规则 → 事实 → 决策 → 动作；每步可回放、可撤销 | 已实现 |
| 任务编排 | Rundeck/StackStorm/Windmill 的剧本与审批 | 审批队列 + 风险分级 + 双钥闸门；动作带回执 | 已实现 |
| 指标与告警 | Prometheus/Grafana/Alertmanager 的采集与通知 | 内置采集器、规则引擎、只读面板；通知通道可插拔 | 已实现（单机） |
| 可用性探针 | Uptime Kuma/Gatus/Healthchecks 的探测与状态页 | HTTP/TCP/ICMP/DNS 探针；状态写入审计 | 已实现 |
| AI 辅助诊断 | HolmesGPT/K8sGPT 的知识检索与根因建议 | 确定性诊断链 + 提案 schema 校验；不依赖模型 | 部分（无本地推理） |
| 主机安全 | Wazuh/OSSEC/AIDE 的完整性与入侵检测 | 完整性基线、rootkit 特征、合规判据 | 已实现（单机） |
| 入侵拦截 | CrowdSec/Fail2ban 的封禁与解封 | 场景引擎、五级处置、自动解除、信誉库 | 已实现 |
| Agent 编排 | LangGraph/CrewAI/AutoGen 的多角色协作 | 单进程确定性执行链；提案与执行分离 | 已实现（无多角色） |
| 自动更新 | Sparkle/Omaha 的签名更新与回滚 | 更新清单 + sha256 + 暂存；离线可校验 | 已实现（手动替换） |
| 发布治理 | 版本台账 + 回执 + 门禁 | 预检、seal、回执、撤回、逐版快照 | 已实现 |
| 集群编排 | Kubernetes 控制器模式 | 多节点任务下发与凭据隔离 | 部分 |
| 可视化大屏 | Netdata/Zabbix 的指标面板 | 只读 Web 面板 + 告警卡片 | 已实现（轻量） |

## 3. 未采纳的做法

- 不引入外部编排框架作为运行时依赖：会扩大攻击面与部署复杂度。
- 不采用插件化执行器动态加载任意代码：插件仅限受信来源，并有静态扫描与权限门。
- 不做“本地大模型推理”：当前以确定性规则与可验证提案为主，避免不可解释行为。
- 不做增量二进制差分更新：先保证全量包可校验、可回滚，增量属于后续优化。

## 4. 结论

本项目在“可验证执行、回执链、预算约束、发布治理”上形成了独立实现；
在集群编排、分布式告警、增量更新方面仍有明确差距，已列入后续版本段，
不以“功能数量对齐”为目标，而以“每个能力可验证、可回滚”为准入条件。
