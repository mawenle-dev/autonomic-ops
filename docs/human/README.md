# 项目说明（运维与发布）

## 概述

AutonomicOps 是运行在 Linux 主机上的自治运维代理，包含指标采集、事实检测、
规则引擎、策略判定、动作执行、回执与反账、审计与面板。项目同时提供
AO Release Studio（发布台）：一个本地运行的桌面工具，用于按版本执行预检、
发布、撤回与更新检查。

本文件面向项目维护者与发布操作人员，只描述可执行的操作和可验证的状态。

## 目录职责

| 位置 | 职责 | 使用场景 |
|---|---|---|
| `autonomic-ops/` | 产品源码与发布台账 | 功能开发、版本记录 |
| `release/receipts/` | 每次发布的回执（发布事实） | 核对某一版本是否完成发布 |
| `release/snapshots/` | 每个版本的文档与哈希快照 | 回溯版本内容 |
| `release/updates/` | 更新包与更新清单 | 便携包升级 |
| `data/`（运行时生成） | 运行数据、快照、回执、反账 | 现场排查 |
| `docs/human/` | 面向维护者的操作文档 | 日常操作、发布、升级 |
| `docs/memory/` | 面向后续维护者的工程记忆 | 交接、约束、决策 |
| `docs/handover/` | 交接材料与交付报告 | 项目移交 |

`release/dist/` 存放便携发布台构建产物；`.tools/`、`.vm/`、`.secrets/`
属于本地开发资源，不得打包或外传。

## 当前状态

- 宪法运行时已接入真实执行链：动作执行前后进行预算与契约检查，执行结果写入
  哈希链回执，拒绝动作写入反账。
- 发布门禁由发布器内部执行，外部无法通过参数绕过；HTTP 写操作仅接受 POST，
  并要求本地会话令牌。
- Linux 端到端自测通过；模块契约验收与端到端验收分开统计。
- 当前版本为 `1.0.1`，发布回执见 `release/receipts/1.0.1.json`（`status=published`），
  标签为 `v1.0.1`。`1.0.0` 为手工建立的基线，控制台标记为 `baseline`，不计入回执发布。
- 下一版本为 `1.0.2`（闸门 `fix_snapshot_state`），需在发布台执行预检后发布。

## 日常操作（最短路径）

1. 启动便携发布台：双击 `AO-Release-Studio.exe`，浏览器自动打开本地页面。
2. 页面显示当前版本、上一版本、待发布版本及其交付内容。
3. 执行“预检 Preflight”：全部检查通过后，发布按钮才启用。
4. 执行“发布 Publish”：写入标签、版本台账、变更日志、发布回执与更新频道。
5. 如需撤销：执行“撤回 Retract”，回退版本台账并清理已发布登记，之后同一版本
   可重新发布。
6. 升级便携包：在“更新通道”中检查可用更新，校验哈希后暂存；关闭程序后替换
   便携目录，再重新启动。

## 运行限制

1. 发布依赖 git 可执行文件。Windows 本机未安装 git 时，发布会返回
   `git_not_available`，不会写入任何版本状态。正式发布应在 WSL/Linux 或已安装
   git 的主机执行。
2. 发布台仅监听 `127.0.0.1`，页面令牌每次启动随机生成。
3. 版本推进一次一级、每日最多一次，禁止跳版与批量发布。

## 故障排查入口

- 发布失败：查看 `release/receipts/<版本>.json` 中的 `tag_log` 与 `checks`。
- 缺少回执：查看 `data/receipts/receipts.jsonl` 最后一条记录及链校验结果。
- 动作被拒：查看 `data/ledger/negative.jsonl` 的 `reason_code`。
- 端到端健康：在 Linux 环境执行 `bash tests/selftest.sh`。
