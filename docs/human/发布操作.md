# 发布与回滚操作规范

## 0. 环境准备

发布操作要求运行环境存在 `git`。Windows 主机未安装 git 时，发布器会在写入任何
状态之前返回 `git_not_available`；不会产生半成品回执，也不会推进版本号。

可用环境：

- WSL/Linux 源码模式：
  ```bash
  cd autonomic-ops
  PYTHONPATH=src python3 -m studio.app --no-browser --port 8765
  ```
  浏览器访问 `http://127.0.0.1:8765/`。
- 已安装 git 的 Windows 主机：运行便携包中的 `AO-Release-Studio.exe`。

发布台不负责推送远端仓库。GitHub 推送为独立步骤，所需凭据在最后一节准备。

## 1. 预检

页面执行“预检 Preflight”，或在 Linux 源码目录执行：

```bash
python3 - <<'PY'
import sys; sys.path.insert(0, ".")
from studio.core import ReleaseStudio, build_preflight
st = ReleaseStudio(".")
r = build_preflight(".", st).run()
print("OK" if r["ok"] else "RED")
for c in r["checks"]:
    print(("PASS" if c["ok"] else "FAIL"), c["name"], c["output"][-200:])
PY
```

检查项与失败含义：

| 检查项 | 失败含义 |
|---|---|
| roadmap | 版本不连续、重复，或当前版本不在台账内 |
| manifest | 便携包缺少 MANIFEST，或文件哈希不符 |
| compile（源码模式） | 语法错误，或 `src/` 下无 Python 文件 |
| unit tests（源码模式） | 单元测试失败 |
| builtin self-test（冻结模式） | 预算、回执、Ed25519、账本自检失败 |

任一检查失败时，发布按钮在代码层禁用，不依赖界面提示。

## 2. 发布

页面执行“发布 Publish”。等价调用：

```python
st.publish(gate="<next_detail.gate>", notes="<next_detail.deliver>")
```

发布流程：

1. 发布器重新执行预检，不接受调用方传入的通过标记；
2. 对 `src/` 逐文件计算 sha256 并生成根哈希（seal）；
3. 创建 `v<版本>` 标签；
4. 成功后更新 `release/release.yaml`、`CHANGELOG.md`、`release/channel/version.json`，
   写入 `release/receipts/<版本>.json`，并生成 `release/docs/<版本>.md` 快照；
5. 失败时只写回执（`status=tag_failed`），版本号保持不变。

约束：版本单步推进，每日最多发布一次。

## 3. 撤回

页面执行“撤回 Retract”。等价调用：

```python
st.retract("1.0.1")
```

执行内容：

- 删除 `v1.0.1` 标签；
- 将回执状态标记为 `retracted`；
- 从 `release/released.json` 移除该版本；
- 将 `release/release.yaml` 与 `release/channel/version.json` 回退到上一版本。

撤回不删除历史文档快照；撤回后同一版本可重新发布。

## 4. 便携包升级

1. 在发布台“更新通道”执行“检查更新”；
2. 读取 `release/updates/manifest.json`，仅展示高于当前版本的条目；
3. 每个条目校验文件存在性与 sha256，校验通过后执行“暂存”；
4. 暂存文件写入 `updates/staged/<版本>.zip`，程序不会自动替换自身；
5. 关闭程序，解压暂存包并替换便携目录，重新启动完成升级。

更新清单由 `tools/update_manifest.py` 生成，也可用 `--check` 复核现有包。

## 5. GitHub 推送（需要维护者凭据）

发布台不包含远端凭据。推送前需要：

1. 在 GitHub 创建 fine-grained PAT，仅授予目标仓库的 `Contents: Read/Write`
   与创建 Release 所需权限；
2. 将令牌保存到 `autonomic-ops/.secrets/github_token`（该目录已被忽略）；
3. 确认远端地址：`git remote -v`；
4. 先执行 dry-run：
   ```bash
   python3 -m autonomic.cli github-release --version 1.0.1 --dry-run
   ```
5. 确认输出无误后再执行 apply。

凭据仅在需要推送时准备，不写入仓库、不放入发布包、不出现在日志中。

## 6. 发布后核对

- `release/receipts/<版本>.json` 存在，`status=published`，`seal.root` 非空；
- `git tag -l` 包含 `v<版本>`；
- `release/channel/version.json` 与 `release/release.yaml` 的版本一致；
- `release/docs/<版本>.md` 内容与 `versions.yaml` 对应条目一致；
- `release/snapshots/v<版本>/MANIFEST.json` 可用于离线核对文档快照。
